# المخطط التنفيذي الشامل — Laurette Employee Operations OS
الإصدار 1.0 — 31 أكتوبر 2026
المستودع المستهدف: https://github.com/LauretteTravel/laurette-platform
الحالة: مواصفات مقترحة؛ لم يُفحص الكود أو قاعدة البيانات بعد. يجب على المنفّذ التدقيق قبل التنفيذ.

## 1. الرسالة الرئيسية للوكيل البرمجي
أنت فريق متكامل من مدير عمليات شركة سياحة متعددة الفروع، مهندس منتجات، مصمم UX/UI، مهندس نظم، مختص أمن، مهندس قواعد بيانات، ومختبر جودة. طوّر قسم الموظفين الحالي في Laurette Travel إلى منصة تشغيل يومية متكاملة. لا تهدم الموقع الحالي ولا تعِد كتابة المشروع من الصفر. افحص المستودع والاعتمادات والمسارات وقاعدة البيانات والصلاحيات والبيانات أولاً. أنشئ فرعاً مستقلاً، نفّذ تدريجياً، اختبر، افتح Pull Request ولا تدمج دون موافقة. لا تدّعِ عمل ميزة قبل اتصالها فعلياً بالبيانات.

## 2. مبادئ المنتج
- واجهة عربية RTL أولاً مع إنجليزية اختيارية، متجاوبة للكمبيوتر والجوال، تصميم عال الجودة بهوية لوريت؛ الحفاظ على الشعار والألوان والخطوط الحالية أو اقتراح تطويرها بموافقة.
- الواجهة تعطي المستخدم ما يحتاجه حسب دوره؛ 3 نقرات كحد مستهدف للوصول للمهام الأساسية.
- الحركة خفيفة ومفيدة: انتقالات 150–250ms، microinteractions، skeleton loaders، احترام prefers-reduced-motion؛ لا مؤثرات تبطئ الإنتاجية.
- كل عنصر قابل للنقر له فعل حقيقي، حالات تحميل وخطأ وفراغ، لا بيانات وهمية في الإنتاج.
- السرعة والأمان وقابلية التدقيق أهم من الزينة.

## 3. الأدوار والصلاحيات والفروع
الأدوار المقترحة: مالك النظام، مدير عام، مدير فرع، مشرف قسم، موظف مبيعات/حجوزات، موظف عمليات/تأشيرات، محاسب، قارئ تقارير. الصلاحيات دقيقة بحسب الإجراء والفرع والقسم والملكية: view/create/edit/assign/transfer/approve/export/delete. المدير ينشئ الموظف بالاسم والقسم والفرع واسم مستخدم فريد، ويضبط صلاحياته. لكل موظف كلمة مرور خاصة غير محددة بعدد أرقام أو أحرف ثابت، مع حد أدنى أمني معقول (مثلاً 12 حرفاً)، دعم عبارات المرور الطويلة، تخزين hash آمن عبر مزود الهوية، إعادة تعيين آمنة، MFA اختياري أو مطلوب للمسؤولين، جلسات محدودة وإبطال وصول عند التعطيل. لا تخزن كلمات المرور نصاً ولا تعرضها للمدير. طبّق RBAC على الخادم وقاعدة البيانات، لا في الواجهة فقط. الموظف قد يعمل في أكثر من فرع أو قسم بتفويض صريح.

## 4. هيكل التنقل
الشريط الجانبي: الرئيسية / صندوق الطلبات / العملاء CRM / مهامي / لوحة الفريق / الحجوزات / القسائم / البرامج والعروض / الإشعارات والتعاميم / التقارير / المالية بحسب الصلاحيات / الموظفون والفروع / الإعدادات. الشريط العلوي الثابت: بحث شامل، محوّل عملات إلى JOD، إنشاء سريع (+)، مركز إشعارات، ملف المستخدم، اختيار الفرع. لا تكرر نفس الوظيفة في صفحات مشتتة.

## 5. لوحة القيادة
للموظف: الطلبات الجديدة، المتأخرة، المتابعة اليوم، حجوزات قيد التأكيد، مهماتي، آخر النشاطات، إنشاء طلب خلال ثوان. للمدير: ملخص كل فرع، طلبات غير مخصصة، متوسط زمن أول رد، نسب التحويل، قيمة المبيعات، الربح الإجمالي والصافي إذا توافرت التكاليف، التحصيل والديون، المهام المتأخرة، ضغط العمل، أداء الأقسام. فلاتر اليوم/الأسبوع/الشهر/فترة مخصصة والفرع والموظف والقناة. كل رقم قابل للنقر ويفتح سجلاته الأصلية. فرّق بوضوح بين حجوزات مؤكدة، مبيعات، تحصيلات، أرباح، تقديرات.

## 6. دورة حياة طلب العميل — المصدر الواحد للحقيقة
حالات مقترحة: جديد → تم تعيينه → جارٍ التواصل → تأهيل الاحتياج → إعداد عرض → أُرسل العرض → متابعة/تفاوض → موافقة العميل → انتظار الدفع/التأكيد → حجز مؤكد → تنفيذ الخدمة → مكتمل. فروع نهائية: خاسر (سبب إلزامي)، ملغى، مكرر، مؤجل (موعد متابعة إلزامي). ليست كل الخدمات تمر بكل الحالات؛ مسارات خاصة للتذاكر، الفنادق، التأشيرات، العمرة، البرامج.
لكل طلب: رقم فريد، العميل ووسيلة التواصل، الفرع، المصدر (واتساب/موقع/اتصال/حملة/إحالة)، نوع الخدمة، الأولوية، مالك الطلب، المشاركون، حالة، قيمة تقديرية وعملة، تاريخ استحقاق، موعد متابعة، ملفات، ملاحظات داخلية، سجل أحداث، ارتباط بالحجز والفاتورة والقسيمة. لا يسمح بإغلاق طلب دون سبب أو مخرجات. عند تحويله ينتقل المسؤول مع إشعار وسجل كامل، مع خيار قبول التحويل أو تصعيده لتفادي ضياعه. كشف التكرار برقم الهاتف بعد توحيده، مع السماح بتعدد طلبات العميل.

## 7. المهام والتعاون
مهام فردية وجماعية، مرتبطة بطلب أو مستقلة، وصف، تاريخ استحقاق، أولوية، قسم وفرع، قائمة فرعية، مرفقات، تعليقات، ذكر @، تحديثات الحالة، تاريخ نقل الملكية. إنشاء مهمة نصية أو رسالة صوتية أو صورة أو مستند؛ رفع آمن مع معاينة وتشغيل صوت داخل النظام؛ حدود حجم ونوع الملف وفحص ملفات وتحكم في الوصول. التحويل بين الموظفين وفق الصلاحيات مع سبب، سجل من/إلى، إشعار المستلم، وعدم فقدان سياق الطلب. حالات: جديدة، قيد العمل، تنتظر طرفاً آخر، بحاجة مراجعة، مكتملة، ملغاة. SLA وتنبيه قبل التأخير وتصعيد تدريجي دون إغراق بالإشعارات. مدير الفريق يرى لوحة Kanban وقائمة وتقويم عبء العمل.

## 8. مركز الإشعارات والتعاميم
جرس أعلى الصفحة مع عداد غير مقروء، قائمة منظمة (مهمة، تحويل، ذكر، متابعة، حجز، تعميم)، فلاتر، روابط مباشرة، إعدادات إشعارات. التعاميم الإدارية منفصلة عن التنبيهات العادية: عنوان، مستوى أهمية، فروع/أقسام مستهدفة، تاريخ صلاحية، مرفقات، إقرار قراءة للسياسات المهمة، لوحة تبين من قرأ ومن لم يقرأ. إشعارات فورية عند توفر بنية realtime، وإلا polling مدروس. تجنب إرسال بيانات حساسة عبر push خارجي.

## 9. استوديو القسائم — نطاق محدود عمداً
نوعان فقط في المرحلة الأساسية: (أ) قسيمة/تأكيد تذكرة طيران (ب) قسيمة حجز فندق. لا تخلطها بقسائم الحج ولا تحذف بيانات حج سابقة. استوديو مستقل داخل الموظفين مع قوالب هوية لوريت، معاينة مباشرة، PDF A4، لغة عربية/إنجليزية عند الحاجة، طباعة ومشاركة. التذكرة: اسم الراكب كما في الجواز، PNR، رقم التذكرة إن وجد، شركة الطيران، القطاعات، المطارات، تواريخ وأوقات محلية مع منطقة زمنية، الأمتعة، حالة الإصدار، شروط مهمة، بيانات الاتصال. الفندق: أسماء النزلاء، اسم الفندق والعنوان، تواريخ check-in/out، عدد الليالي، نوع الغرفة، الوجبات، عدد الضيوف، مرجع الحجز، حالة التأكيد، سياسة الإلغاء، ملاحظات الاستقبال. لا تظهر عبارة «مؤكد» إلا إذا كانت الحالة مؤكدة فعلاً.
لكل قسيمة UUID داخلي ورقم مرجعي بشري فريد مثل LRT-FLT-2026-000001 أو LRT-HTL-2026-000001، ربط بطلب وحجز، تاريخ إصدار، منشئ، إصدار/نسخة، سجل تعديلات. يمكن تعديل المسودة؛ تعديل قسيمة منشورة ينشئ إصداراً جديداً ويحفظ السابقة، مع وسم «ملغاة/مستبدلة» عند اللزوم. أرشيف قابل للبحث بالمرجع والاسم والعميل والتاريخ والحالة، تنزيل النسخ القديمة وفق الصلاحيات. حماية الملفات والروابط من الوصول العام غير المصرح.

## 10. إدارة البرامج والعروض
تصنيف حسب الخدمة: عمرة، حج (إن كان مدعوماً أصلاً)، تركيا، مصر، أوروبا، شرق آسيا، شهر عسل، رحلات بحرية، عروض تذاكر، فنادق، تأشيرات، وتصنيفات قابلة للإدارة. لكل برنامج: عنوان، وجهة، فترة، صلاحية السعر، سعر البيع/التكلفة/العملة، إشغال، شروط، ما يشمل/لا يشمل، جدول رحلة، ملفات مصدر، إصدار، حالة مسودة/مراجعة/منشور/منتهي، الفرع، المسؤول. بحث وفلترة وأرشفة ومراجعة التغييرات.
استيراد PDF/DOCX: استخراج النص والجداول → تحليل حقول الأسعار والعملات والتواريخ والشروط → عرض مقارنة بالبيانات الحالية مع الثقة والمصدر → مراجعة بشرية واعتماد → تحديث نسخة البرنامج والصفحات المتأثرة. لا تنشر أسعاراً تلقائياً دون اعتماد؛ لا تخلط سعر الفرد مع سعر الغرفة أو السعر الرباعي مع المزدوج؛ تحقق من صلاحية العرض وتواريخ السفر وتعدد العملات. الملفات الممسوحة قد تحتاج OCR؛ عند فشل الاستخراج اعرض خطأً واضحاً وأبقِ الملف للمراجعة. احتفظ بالأصل وسجل من وافق على النشر. مزامنة العرض المنشور مع واجهة الموقع الحالية دون فقدان العروض القديمة.

## 11. التقارير والتحليلات
لوحات مخصصة للإدارة والموظف، مع مقارنة فترات، أهداف مقابل نتائج، تفاصيل drill-down، تصدير CSV/PDF بحسب الصلاحية. المقاييس: عدد العملاء الجدد، الطلبات بحسب المصدر والخدمة والفرع، معدل أول رد، زمن إغلاق الطلب، التحويل إلى حجز، معدل الخسارة وأسبابها، المبيعات بحسب تاريخ التأكيد، إيراد/تكلفة/هامش وربح، تحصيلات ومديونيات، طلبات متأخرة، إنتاجية الموظف وجودة الخدمة، نشاط المهام ونسب الالتزام، أداء الحملات عند ربط مصدر البيانات. وثّق تعريف كل KPI، المنطقة الزمنية Asia/Amman، العملة الأساسية JOD، طريقة تحويل العملات ومصدر السعر. لا تخلط الأرباح التقديرية بالمحققة؛ امنع عرض أرقام مفبركة عند غياب البيانات.

## 12. أداة أسعار الصرف
شريط صغير ثابت في الأعلى يعرض عملات مختارة (USD/EUR/SAR/AED/TRY وغيرها) مقابل الدينار الأردني؛ اختيار عملة وحاسبة سريعة في popover متاحة بكل الصفحات. عرض مصدر سعر الصرف، توقيت آخر تحديث، حالة انقطاع الخدمة، وتمييز السعر الإرشادي عن سعر البيع/الشراء الفعلي. تخزين مؤقت وتحديث دوري عبر خدمة موثوقة مع API key في الخادم إن لزم. عدم افتراض سعر مباشر ثابت أو حساب مالي محاسبي بسعر غير معتمد.

## 13. اقتراحات إضافية تستحق التنفيذ
- صندوق طلبات غير مخصصة يمنع ضياع العملاء.
- قوالب ردود ومتابعات واتساب قابلة للتخصيص، روابط WhatsApp فقط في البداية؛ لا تدّعِ تكاملاً رسمياً دون API وتفويض.
- لوحة تحذيرات تشغيلية: موعد إصدار تذكرة، انتهاء خيار حجز، موعد دفع، قرب سفر، نقص بيانات جواز.
- سجل معرفة داخلي: سياسات الشركات، تعليمات التأشيرات، أسئلة متكررة؛ مع تاريخ تحديث ومسؤول محتوى.
- قائمة تحقق قبل تأكيد الحجز وإصدار القسيمة.
- استيراد بيانات قديمة بخطة mapping واكتشاف تكرار ونسخ احتياطي.
- لوحة صحة النظام: أخطاء تكامل، وظائف مجدولة، ملفات فاشلة، نسخ احتياطية.

## 14. أشياء لا أوصي بها الآن
لا تبنِ محادثة عامة بديلة عن واتساب، ولا نظام محاسبة كامل من الصفر، ولا ذكاء اصطناعي يغيّر أسعار العملاء بلا مراجعة، ولا رسوم متحركة ثلاثية الأبعاد في كل شاشة، ولا تعيد كتابة الموقع بالكامل. لا تنشئ قسائم حج جديدة ما دام نطاق الاستوديو المطلوب هو الطيران والفنادق فقط. ابدأ بنظام تشغيل متين ثم توسّع عند ظهور حاجة حقيقية.

## 15. نموذج البيانات المبدئي (يعدل بعد التدقيق)
branches, departments, users/profiles, memberships, roles, permissions, role_permissions, customers, customer_contacts, leads/requests, request_events, assignments, tasks, task_comments, task_attachments, notifications, announcements, announcement_acknowledgements, bookings, vouchers, voucher_versions, programs, program_versions, program_files, import_jobs, exchange_rate_snapshots, activity_audit_logs. استخدم علاقات FK وفهارس وقيود unique وtimestamps وsoft delete عند الحاجة؛ تجنب تكرار بيانات العملاء والطلبات. سياسات RLS أو طبقة تفويض مكافئة. تخزين الملفات في storage خاص، وليس روابط عامة دائمة.

## 16. واجهات وتجارب رئيسية
1) لوحة الموظف: شريط علوي + بطاقة «أول شيء يجب فعله الآن» + طلبات تحتاج رد + مهام اليوم + نشاط الفريق.
2) لوحة المدير: بطاقات KPIs قابلة للفتح + قائمة مخاطر + أداء الفروع + pipeline + عبء الفريق.
3) تفاصيل الطلب: رأس ثابت بالعميل والحالة والمسؤول، timeline زمني، تبويبات محادثات/ملفات/عروض/حجوزات/مهام، زر الإجراء التالي.
4) المهام: قائمة/Kanban مع لوحة تفاصيل جانبية، تسجيل صوت مباشر إذا سمح المتصفح، رفع صورة/ملف، تحويل وتاريخ كامل.
5) استوديو القسائم: نموذج يسار/معاينة يمين على سطح المكتب، خطوات متدرجة على الهاتف، أزرار حفظ مسودة/إصدار/طباعة/أرشيف.
6) استيراد البرامج: ارفع → استخرج → طابق → راجع → اعتمد → انشر؛ اعرض فروق الحقول قبل وبعد.

## 17. المتطلبات غير الوظيفية والأمن
مصادقة آمنة، منع الوصول الأفقي بين الفروع، اختبارات صلاحيات، rate limiting، CSRF/XSS/SQL injection defenses حسب المكدس، تحقق خادمي من المدخلات، فحص نوع وحجم المرفقات، حماية البيانات الشخصية والجوازات، تشفير أثناء النقل، نسخ احتياطية قابلة للاستعادة، مراقبة أخطاء، سجلات تدقيق لا يستطيع الموظف محوها، سياسة احتفاظ وحذف، مراقبة فشل الوظائف. معايير وصول WCAG 2.2 AA كهدف، تنقل بلوحة المفاتيح، تباين مناسب، دعم شاشة صغيرة، قياس الأداء الحقيقي.

## 18. مراحل التنفيذ الإلزامية
المرحلة صفر — تدقيق: جرد الصفحات والأزرار والبيانات والـAPI والمصادقة وقاعدة البيانات والتبعيات، قائمة ما يعمل وما لا يعمل، مخطط معماري ومخاطر ونسخة احتياطية. لا تبدأ بهدم أي جزء.
المرحلة 1 — الأساس: نظام هوية وصلاحيات وفروع وموظفين، تخطيط الواجهة، سجل تدقيق، ترحيل آمن.
المرحلة 2 — CRM والمهام: صندوق الطلبات ودورة الحياة، تعيين وتحويل، مرفقات وصوت وإشعارات.
المرحلة 3 — القسائم: الطيران والفنادق، إصدار PDF، رقم مرجعي، أرشيف ونسخ.
المرحلة 4 — البرامج: تصنيفات، محرر أسعار وشروط، استيراد PDF/DOCX بمراجعة بشرية.
المرحلة 5 — التحليلات: KPIs موثقة، تقارير الفروع والموظفين والمالية، تحويل عملات.
المرحلة 6 — الصقل: اختبارات وصول وأداء وأمان، تحسينات UI والحركات، توثيق وتسليم.
بعد كل مرحلة: تقرير ملفات متغيرة، ترحيلات DB، لقطات شاشة، اختبارات، مشاكل معروفة، وخطوة rollback.

## 19. معايير القبول
- يمكن للمدير إنشاء موظف وربطه بفرع وقسم وصلاحيات، ويمنع الخادم الوصول غير المصرح.
- إنشاء طلب جديد وتعيينه ونقله بين موظفين يحافظ على السجل والملفات ويطلق إشعاراً.
- لا يختفي طلب دون مالك أو من صندوق غير المخصص؛ يظهر المتأخر بوضوح.
- مهمة بصوت أو صورة أو نص يمكن حفظها وعرضها ونقلها وتوثيقها.
