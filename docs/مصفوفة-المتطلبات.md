# مصفوفة المتطلبات (تحليل ما قبل التنفيذ)

> **ملاحظة:** أُعدّت هذه المصفوفة أثناء التحليل، قبل كتابة الكود، لذلك تصف مسارات وجداول **مقترحة**. أسماء النهايات والجداول المنفَّذة فعليًا موجودة في `README.md` و`docs/API.md`، وحالة كل بند في `docs/التقرير-النهائي.md`. تُحفظ هنا كمرجع للتغطية ومعايير القبول.

**الغرض:** تحويل الموجز العربي (14 مرحلة) إلى بنود قابلة للاختبار، على هدف تنفيذي واحد: خادم Node.js بلا اعتماديات (`node:http`) + SQLite (`node:sqlite`) + واجهة عربية RTL ثابتة. كل ما يحتاج Amadeus/Sabre أو دفعاً أو SMS/WhatsApp Business API أو بريداً أو مزوّد LLM هو **مهد تكامل فقط**، لا بند يُنفَّذ الآن.

**اصطلاحات تُستخدم في معايير القبول:**
- المسارات: `POST /api/requests` (طيران)، `/api/hotels`، `/api/programs`، `/api/visas`، `/api/umrah`، `/api/consultations`.
- البادئات: `LT-FL` / `LT-HT` / `LT-PG` / `LT-VS` / `LT-UM` / `LT-CS` + 6 خانات `[A-Z0-9]`.
- قاعدة البيانات: `data/laurette.db`؛ جداول: `requests`, `request_events`, `customers`, `packages`, `hotels`, `staff`, `sessions`, `documents`, `knowledge`, `chats`.
- التصنيف: **ينفذ محلياً** = يكتمل بـ Node+SQLite وحده · **ينفذ جزئياً** = يُبنى محلياً لكن جودة/اكتمال البند تعتمد على مورد غير برمجي (أصول صور، محتوى بشري، تحقق نوع الملفات) · **يحتاج خدمة خارجية** = لا معيار قبول يتحقق بلا مزوّد مدفوع/معتمد.

## مخاطر التنفيذ

- **إصدار Node يحكم المشروع كله.** `node:sqlite` أُضيف في 22.5.0 وأُزيل العلم التجريبي في 22.13/23.4 (RC في 25.7). خادم بـ Node 20 أو أقل = لا مشروع قبل كتابة سطر. التخفيف: فحص الإصدار أول متطلب نشر، والهدف 24 LTS.
- **تعارض صريح بين تعليمات الموجز والواقع.** «لا تعِد بناء المشروع من الصفر» + «لا تعطّل الموقع الحالي» لا يمكن الوفاء بهما حرفياً مع هدف Node+SQLite، لأن الموقع الحالي بلا خادم ولا قاعدة بيانات: كل الحالة في `localStorage` والمنطق في ملف واحد. ما يُحفظ فعلاً هو الكتالوج والهوية وتدفق واتساب، لا الشيفرة. التخفيف: إعلان هذا للعميل واعتماد قائمة الانحدار (بند 2) بدل «عدم إعادة البناء».
- **نموذج الثقة الحالي غير موجود.** دخول الإدارة تحقق في المتصفح (`work/legacy.js:201`) وجلسة في `sessionStorage`؛ أي مستخدم يستطيع تعديل بياناته المحلية. الانتقال للخادم يغيّر النموذج كلياً، وما في متصفح الموظف ليس مصدر بيانات.
- **الأسعار المخزّنة هي المخاطرة الأخلاقية الأولى.** الموجز يكرر «لا سعر غير معتمد» ثلاث مرات، والأسعار الحالية مكتوبة داخل JS. أي صف يُستورد بـ `price_confirmed = 1` بلا مراجعة بشرية ينشر التزاماً سعرياً لم توافق عليه الإدارة. التخفيف: القيمة الافتراضية 0 عند الترحيل، وتأكيد المالك لكل برنامج قبل الظهور.
- **عزل مستندات الجوازات.** رفع `multipart` بلا مكتبات + تحقق نوع فعلي + تخزين خارج `public/` + تحميل بجلسة. أي خطأ في أحد هذه الأربعة = تسريب مستندات هوية، وهو أخطر من كل بند آخر في المصفوفة.
- **التكامل الخارجي خارج سيطرة الجدول.** بلا Amadeus/Sabre لا سعر ولا توفر (بندا 19 و23)؛ الحساب يحتاج اعتماداً وتكلفة لكل معاملة. لا يمكن وعد العميل بموعد «أسعار حقيقية».
- **الإشعارات ليست زراً.** WhatsApp Business API يفرض حساب أعمال موثّقاً وقوالب معتمدة للرسائل المُبتدأة من الشركة، وSMS بتكلفة لكل رسالة. بلا ذلك يبقى `/track` هو قناة المتابعة الوحيدة — وهذا مقبول لكن يجب قوله صراحة.
- **SQLite تكفي اليوم ولا تُقاس بالغد.** وضع WAL يكفي لعشرات الطلبات يومياً؛ عند مئات الكتابات المتزامنة يصبح القفل عنق زجاجة. التخفيف: عزل كل وصول للبيانات في طبقة واحدة حتى يكون الاستبدال لاحقاً بلا إعادة كتابة.

## حدود النسخة الأولى

- **لا حجز فوري ولا دفع إلكتروني:** كل مسار ينتهي بطلب عرض سعر؛ لا بوابة دفع ولا عربون ولا فاتورة.
- **لا أسعار طيران أو فنادق حية ولا عدّاد مقاعد:** الصفحات تعرض عروض الشركة المعتمدة فقط.
- **المساعد بلا LLM:** إجابات من قاعدة معرفة محلية + مطابقة نوايا؛ لا حوار حر ولا ذاكرة طويلة، ويحوّل لموظف عند الشك.
- **لا إشعارات خارجية تلقائية:** لا SMS ولا WhatsApp API ولا بريد؛ حالة الطلب تُقرأ من `/track`.
- **رفع المستندات للتأشيرات فقط**، بحد 10MB وأنواع محددة؛ لا رفع عام.
- **الإنجليزية هيكلية لا كاملة:** RTL عربي كامل، و`/en` بمسارات ونصوص أساسية دون ترجمة كل المحتوى.
- **فرع واحد بصلاحيات مسطّحة:** لا multi-tenant ولا فصل صلاحيات بين عمّان وإربد.
- **لا تقارير مالية ولا تكامل محاسبة/ERP.**
