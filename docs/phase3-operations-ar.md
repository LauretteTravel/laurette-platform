# تشغيل المرحلة الثالثة والرجوع

هذه تعليمات لمرشح مراجعة، وليست دليل نشر منفذ. لا تعديل للإنتاج أو خطة Render أو إعداد n8n أو بوابة رفع المرفقات ضمن المرحلة الثالثة. لا نشر أو دمج إلا بطلب صريح يخص هذه المرحلة.

## الترحيل والصلاحيات

الترحيل 6 يضيف voucher_bookings وvoucher_sequences وemployee_vouchers وvoucher_versions وvoucher_events وفهارسها وحماية الهوية وسجلات append-only. لا يُعدل أي ترحيل من 1–5 ولا أي بيانات قديمة أو مسودة localStorage. runner ينشئ نسخة SQLite متسقة خاصة قبل الخطوة. لا توجد منحة تلقائية للأدوار القديمة.

الصلاحيات الجديدة: vouchers:read/write/issue/cancel/export. تحتاج العمليات أيضًا vouchers:read وrequests:read، مع نطاق الطلب الحالي. المسؤول ذو \* يبدأ مباشرة؛ راجع منح بقية الموظفين من إدارة الأدوار، ولا تمنح إصدارًا أو إلغاءً أو تنزيلًا لمجرد السماح بالحفظ. MFA وmust_change والجلسات وCSRF لا تُعطل. بعد قراءة جسم أي عملية تعديل يُعاد تحميل الجلسة والصلاحية قبل الكتابة؛ سحب صلاحية أثناء الإرسال يمنع العملية.

تغيير مالك الطلب أو فرعه أو السياق المفوض يغيّر الوصول إلى كل قسائمه، دون منح وصول مستقل من سجل القسيمة. UUID ليس رمز وصول، وكل قائمة أو مستند أو نسخة قديمة تحتاج جلسة وصلاحية. لا مسار عام أو رابط مشاركة دائم أو API لتنزيل نسخة دون تسجيل دخول. يمكن للموظف المخول مشاركة PDF الذي نزله بنفسه عبر قنوات الشركة المعتمدة؛ لا إرسال تلقائي أو خدمة مشاركة خارجية جديدة.

## دورة القسيمة

إنشاء مسودة مرتبطة بطلب، ثم حفظ البيانات وسبب العملية. المرجع يولده الخادم بمعاملة متسلسلة حسب النوع والسنة في Asia/Amman. سجل الحجز داخلي، ولا ينشئ حجزًا لدى مزود أو عملية دفع. يحتاج الإصدار إلى طلب confirmed وبيانات مكتملة؛ لا يعدل حالة الطلب تلقائيًا. رقم تذكرة الطيران اختياري، ولا يُدعى اتصال بنظام شركة الطيران.

التعديل على الصادر يبدأ مسودة مراجعة؛ يظل الصادر السابق محفوظًا. إصدار البديل يزيد رقم النسخة ويضع وسم مستبدلة على القديمة عند فتحها لاحقًا. الإلغاء يحفظ السبب والنسخ ولا يمحو سجلًا. إذا أُلغي الطلب نفسه أو أُعيد للمراجعة، يتغير وسم المستند عند طلبه حتى لا يظهر كتأكيد حالي. الملفات المنزلة سابقًا خارج النظام لا يمكن تعديلها أو سحبها عن بعد.

النسخ تحفظ البيانات والهوية والشعار والتوقيت وSHA256. المستند الخاص يعاد بناؤه من snapshot الإصدار، مع وسم الحالة الحالية. PDF يتولد في المتصفح بالمكتبات المحلية؛ لا يُرفع PDF أو يُرسل لمزود فحص أو تخزين خارجي. PDF نسخة رسومية تدعم العربية، وليست ملفًا نصيًا قابلًا للبحث أو نموذجًا تفاعليًا أو توقيعًا رقميًا أو فاتورة. لا يُدعى تطابق بايتات كل إعادة توليد (بيانات إنشاء PDF قد تختلف). لا تستخدم حفظ PDF كبديل للتحقق من الحجز لدى المزود.

الحدود: 30 اسمًا، 6 قطاعات، 365 ليلة، و50 إصدارًا للقسيمة. تعرض صفحة الأرشيف 25 سجلًا وآخر 100 حدث بالتفصيل مع بقاء الأقدم محفوظًا. البحث بالمرجع أو مرجع الطلب أو أسماء البيانات الحالية/المسودة؛ ابحث بالمرجع لفتح الإصدارات التاريخية. تُحسب الليالي على الخادم. الرحلات تحتاج وقتًا محليًا بإزاحة UTC ومنطقة IANA متطابقين، بما يشمل التوقيت الصيفي. لا أسعار أو تحويل عملات أو بيانات جواز كاملة أو مرفقات جديدة في هذه الدفعة.

## قبل اعتماد النشر

1. راجع الفرع النهائي واختبارات API والمتصفح والـPDF وCI. اختبارات جميع المراحل تبقى مطلوبة، بما فيها القسائم القديمة والتتبع وn8n المصطنع.
2. احتفظ بنسخة خاصة حديثة من مخطط 5، وجرّب 5→6 وإعادة الفتح والاستعادة في عزل. أداة rehearse-private-db.mjs تفتح المصدر read-only، وتقارن القيم وتحفظ النسخ داخل المسار الخاص. لا تشغل تطبيقًا أو seed على نسخة عملاء للفحص، ولا تنقل النسخ أو النتائج التشغيلية إلى GitHub العام.
3. تحقق من مساحة القرص الخاصة والنسخ المستقبلية، ومفاتيح MFA الحالية، واسم الشركة ووسائل الاتصال والشعار قبل الإصدار. لم تتغير خطة الاستضافة، ولا تحتاج المرحلة إلى ClamAV ما دام رفع المرفقات مقفلًا.
4. بعد نشر مصرح به فقط: تحقق من المخطط 6 وسلامة SQLite والفهارس وسجل الترحيلات وبصمات 1–5، ومن الأدوار والسياقات ومراجع القسائم القديمة. لا تضع سجلات مصطنعة في الإنتاج دون نطاق اختبار معتمد.

الرجوع ليس زر Rollback للكود وحده: كود المخطط 5 يرفض قاعدة 6. لا تُسقط الجداول ولا تُغير user_version أو checksum يدويًا. احفظ كل البيانات الجديدة وصالحها في عزل قبل أي استعادة قديمة وبموافقة المالك، أو استخدم إصلاحًا أماميًا متوافقًا. يمكن إزالة منح الإصدار مؤقتًا مع بقاء السجلات. لا توجد استعادة عكسية تلقائية أو حذف لنسخ القسائم.
