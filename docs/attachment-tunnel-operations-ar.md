# ربط فاحص مستقل — تجهيز للمراجعة فقط

تضيف هذه الدفعة طريقة تشغيل اختيارية على Linux لفاحص ClamAV خارج مضيف التطبيق. لا تغيّر أمر التشغيل المعتاد أو Render Blueprint أو قاعدة البيانات أو الترحيلات. لا تنشئ موردًا مدفوعًا ولا تتصل بعنوان افتراضي. اعتماد هذه الشيفرة لا يعني اعتماد مزود أو إرسال ملفات عملاء إليه.

## السلوك

`lib/attachment-tunnel.js` يشغّل OpenSSH دون shell، مع هوية عميل مخصصة وبصمة خادم مثبتة، ويعيد الاتصال بتدرج 1–30 ثانية. تحويل SSH يستمع على loopback فقط ويستهدف `127.0.0.1:3310` على الخادم المعتمد فقط. لا تُعطى عملية SSH متغيرات التطبيق أو مفاتيح MFA أو إعدادات قاعدة البيانات. لا تُسجل المرفقات أو بيانات المصادقة في هذه الأداة.

بوابة التطبيق المحلية تفحص VERSION عبر القناة قبل كل طلب، وترفض التواقيع الأقدم من 14 يومًا أو المستقبلية بأكثر من يوم، والردود الغائبة/المشوهة. الرفض يتم قبل تمرير محتوى المرفق. لا يُخزن الملف لمجرد اجتياز فحص التواقيع: يظل فحص INSTREAM الحالي مطلوبًا، ويظل الرفض 422 عند اكتشاف عينة ضارة و503 عند تعذر الفحص. الحد أربعة اتصالات للبوابة، وفحص VERSION بمهلة ثانيتين، وبقية الاتصال بمهلة خمول 10 ثوانٍ. المهلة الحالية للتطبيق تبقى 10 ثوانٍ؛ يجب قياس الكمون الفعلي قبل الاعتماد.

`tools/start-with-attachment-tunnel.mjs` أمر تشغيل بديل صريح؛ يشرف على النفق وخادم التطبيق معًا ويغلق العمليتين عند SIGTERM/SIGINT أو خروج التطبيق. تعطل النفق لا يعطل الموقع كله؛ يستمر التطبيق وترفض المرفقات غير المفحوصة. فشل الإعداد أو غياب OpenSSH يمنع بدء هذا الأمر. لم يُبدَّل أي أمر تشغيل حالي.

## إعداد خاص بعد اعتماد المزود والمنطقة والتكلفة

1. خادم Linux للفحص فقط بذاكرة تحقق متطلبات ClamAV الرسمية؛ الحد الأدنى 3 GiB والمفضل 4 GiB. يجب اختبار تحديث التواقيع والذاكرة الفعلية، خصوصًا إذا كان عرض المزود يقول 4 GB. مسؤولية تحديث النظام والتواقيع والمراقبة جزء من تشغيل الخادم.
2. إصدار ClamAV مدعوم وصورة مثبتة إلى digest مراجع إن استُخدم Docker. احتفظ بتواقيع FreshClam في تخزين دائم. اربط clamd إلى `127.0.0.1:3310` فقط؛ عند Docker انشر إلى loopback صراحةً. المنفذ الخام بلا تشفير أو مصادقة، ويجب ألا يكون عامًا.
3. إعداد حدود الفحص: `StreamMaxLength` يسمح بـ5 MiB على الأقل، و`MaxThreads 2` وحدود مناسبة للملفات/التفكيك/الوقت مع `AlertExceedsMax yes` حتى لا يتحول تجاوز حد المحرك إلى قبول صامت. لا تضيق التواقيع لتعويض الذاكرة. `FailIfCvdOlderThan 14` حماية إضافية عند بدء clamd ولا يغني عن فحص العمر المستمر في البوابة.
4. عزل ملفات clamd المؤقتة في tmpfs محدود، وعدم تسجيل المحتوى أو أسماء الملفات، ومراجعة swap وcore dumps وسياسة النسخ حتى لا يحتفظ المضيف بملفات مؤقتة. INSTREAM لا يثبت وحده عدم وجود كتابة مؤقتة. قاعدة بيانات التطبيق لا تُنقل إلى خادم الفحص.
5. حساب SSH مخصص بلا جلسات shell. قالب `tools/scanner-host/sshd.conf.example` يقيد الاتصال إلى الوجهة المحددة، مع `MaxSessions 0`. قيّد المفتاح أيضًا بخيارات `restrict,port-forwarding,permitopen="127.0.0.1:3310"` قبل المفتاح العام في authorized_keys. راجع ملكية الملفات وStrictModes والتحقق من الحساب حسب نظام التشغيل. لا تستخدم مفتاح إدارة أو مستودع.
6. ثبت مفتاح الخادم العام ED25519 بعد التحقق من بصمته بقناة إدارة موثوقة. لا تعتمد على ssh-keyscan وحده أو accept-new. قيمة known_hosts تحتاج اسم الخادم، أو `[host]:port` للمنفذ المخصص. الأداة لا تحدّث المفتاح تلقائيًا.

متغيرات الأمر البديل، كلها تضبط خارج Git:

| المتغير                           | الغرض                                                                                                    |
| --------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `ATTACHMENT_SSH_HOST`             | IP أو DNS للمضيف المعتمد؛ إلزامي                                                                         |
| `ATTACHMENT_SSH_USER`             | حساب التحويل المخصص؛ إلزامي                                                                              |
| `ATTACHMENT_SSH_PORT`             | منفذ SSH؛ الافتراضي 22                                                                                   |
| `ATTACHMENT_SSH_KEY_FILE`         | مسار مطلق لمفتاح العميل الخاص؛ ملف مملوك لمستخدم الخدمة وصلاحيات 0600                                    |
| `ATTACHMENT_SSH_KNOWN_HOSTS_FILE` | مسار مطلق لملف مفاتيح الخادم المراجعة، دون فراغات أو علامات اقتباس؛ غير قابل للكتابة من المجموعة/الآخرين |
| `ATTACHMENT_CLAMD_PORT`           | منفذ البوابة المحلية؛ الافتراضي 3310                                                                     |
| `ATTACHMENT_SSH_FORWARD_PORT`     | منفذ التحويل الداخلي المحلي؛ الافتراضي 3311، ويجب أن يختلف عن منفذ البوابة                               |

أمر التشغيل المقترح بعد اعتماد النشر فقط: `node tools/start-with-attachment-tunnel.mjs`. يحتاج OpenSSH في بيئة التشغيل الفعلية؛ لا تفترض أنه مثبت على Render. أي إضافة عميل SSH أو تبديل runtime/مسار DB يحتاج مراجعة واختبارًا مستقلًا، ولم يُنفذ هنا. إذا استُخدم مسار DB مخصص أو مفاتيح MFA حالية فيجب المحافظة عليها. تثبت الأداة مصدر ملفات المفاتيح وقت البدء، ويظل منع العبث بها أثناء التشغيل مسؤولية صلاحيات المضيف.

## التحقق

الاختبارات المحلية تغطي رفض إعدادات الحقن والمسارات غير الآمنة والمنفذين المتعارضين وتواريخ التواقيع غير المقبولة. `tools/tunnel-acceptance.mjs` محصور في CI على Linux، ينشئ مفاتيح مؤقتة ويستخدم SSHD ومحرك ClamAV فعليين مع ملفات مصطنعة فقط. يفحص القبول والكشف وفشل هوية الخادم ومفتاح العميل والتعطل وإعادة الاتصال. يستبدل محرك CI بعد ذلك بمحاكي محلي مضبوط لاختبار منع تمرير المرفق عند قدم التواقيع وإعادة فحصها في كل طلب؛ هذا الجزء ليس إثبات كشف بمحرك حقيقي.

يُعاد أيضًا تشغيل اختبار API بمحرك حقيقي عبر النفق نفسه: رفع مصطنع وتنزيل مطابق ومحمي ورفض الزائر، وفشل الحفظ عند تعذر الفحص.

لا يكفي نجاح CI لاعتماد مضيف جديد: يلزم اختبار فعلي بملفات مصطنعة على المضيف المختار، تحديث تواقيع، قياس ذاكرة وحمل وكمون، والتحقق من إغلاق المنفذ العام ومراقبة التعطل. لا نشر ولا تمرير لملفات عميل قبل اعتماد ذلك صراحةً.

المراجع: [OpenSSH client](https://man.openbsd.org/ssh)، [قيود SSHD](https://man.openbsd.org/sshd_config)، [ذاكرة ClamAV](https://docs.clamav.net/manual/Installing/Docker.html)، [بروتوكول clamd](https://docs.clamav.net/manual/Usage/ClamdProtocol.html)، [إعدادات clamd الرسمية](https://github.com/Cisco-Talos/clamav/blob/main/etc/clamd.conf.sample).
