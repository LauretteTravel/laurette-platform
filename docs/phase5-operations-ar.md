# تشغيل المرحلة الخامسة وتعريف المقاييس

هذا تسليم للمراجعة فوق المرحلة الرابعة، وليس إذنًا بدمجها أو نشرها. لا تُنشأ حجوزات أو دفعات أو عملاء في الإنتاج أثناء الاختبار. الترحيلات 1–7 ثابتة؛ الترحيل 8 يضيف أهداف الأداء وسجلها وفهارس قراءة فقط، دون تعديل صفوف العمل أو منح صلاحيات.

## الصلاحيات والنطاق

- التقارير تحتاج `reports:read` و`requests:read` مع جلسة مكتملة وmust_change وMFA كما يفرضهما الخادم.
- `reports:finance` مستقلة لقراءة الحجوزات والتكاليف والدفعات والأرصدة. لا تُمنح تلقائيًا لمدير يستطيع قراءة التقارير العامة.
- `reports:export` مستقلة لـCSV ومستند PDF؛ لا توسع نطاق القراءة أو تضيف صلاحية مالية. غياب قراءة المهام أو العملاء يجعل مؤشرهما غير متاح.
- `reports:targets` لإنشاء هدف أو تعديل قيمته/إيقافه، وتستلزم MFA. أهداف التحصيل تحتاج الصلاحية المالية أيضًا.
- النطاق الحالي للمؤسسة/الفرع/القسم/المسؤول والعضوية المفوضة يطبق على الملخص والتفاصيل والتصدير والأهداف. طلب المسؤول الفردي يحتاج الفرع والقسم الحاليين أيضًا. تغيير السياق أو سحب العضوية لا يمنح وصولًا للسياق القديم.
- أسماء مرشحي الموظفين تحترم العضويات النشطة في الجهة، لا الفرع الأساسي فقط. لا يظهر هدف يغطي مؤسسة أو فرعًا كاملًا لموظف لا يرى كامل جهة الهدف. التحويل المالي عبر تصدير البيانات أو PDF لا يتجاوز هذه القواعد.

راجع منح الصلاحيات قبل الاستخدام. المرحلة لا تسند صلاحيات مالية تلقائيًا ولا تغيّر حسابات المسؤولين أو إعداد MFA للمستخدم الحقيقي.

## الزمن والمجموعة والمقارنة

منطقة التقارير Asia/Amman. مدخلات التاريخ أيام صحيحة من 2000 إلى 2199، والنطاق 1–366 يومًا. البداية أول لحظة في اليوم المحلي، والنهاية أول لحظة في اليوم التالي غير مشمولة. اختيار أول لحظة يحتفظ بالساعة المتكررة عند الرجوع الشتوي ويتعامل مع منتصف الليل المفقود عند الانتقال الصيفي. تستخدم الحدود IANA/Intl، بما فيها القواعد الأردنية التاريخية، ولا يُفترض +03 لكل السنوات. الفترة السابقة لها عدد الأيام نفسه وتنتهي قبل بداية الحالية.

مجموعة الطلبات تعتمد تاريخ إنشائها، ثم تعرض حالتها وإسنادها الحاليين. السلسلة اليومية تعرض طلبات اليوم وحالتها الحالية، لا عدد تأكيدات حدثت تاريخيًا في ذلك اليوم. المبيعات المسجلة من bookings لها مجموعة منفصلة بحسب confirmed_at. إحصاءات المهام بحسب due_at. نتيجة الهدف لفترته وجهته الكاملتين، وليست جزء الفترة المختارة على الشاشة.

فرق الأعداد مقدار مطلق، وفرق النسب نقاط مئوية؛ التغير النسبي = الفرق ÷ السابق. إذا كان السابق صفرًا فلا تُعرض نسبة نمو مخترعة. مقام صفر أو عينات غائبة يعطي null/«غير متاح»، بينما عدد صفوف مطابق يساوي صفرًا يبقى صفرًا حقيقيًا لسجل النظام.

## المؤشرات ومصادرها

| المؤشر | المصدر والتفسير |
|---|---|
| العملاء الجدد | customers.created_at؛ في النطاق المحدود/المفلتر يلزم طلب مرتبط مرئي ولو أنشئ في فترة مختلفة. لا يشمل حسابات clients غير المرتبطة ولا العملاء غير المسجلين. |
| الطلبات الجديدة | requests.created_at ضمن الأيام المختارة، مع الخدمة والمصدر والفرع المنفذ/المستقبل والقسم والمسؤول الأساسي الحالي. جهات NULL قابلة للتصفية كغير محددة. |
| التأكيد والتحويل | deal_status=won من مجموعة الإنشاء؛ التحويل = المؤكدة/كل الطلبات، والفوز = المؤكدة/(المؤكدة+الملغية). هذا تأكيد طلب في النظام وليس إثبات حجز مورد أو دفع. |
| الخسارة وأسبابها | deal_status=lost وlost_reason الحالي. السبب الناقص «غير مسجل» ولا يُستنتج من النصوص. |
| أول إجراء | first_response_at بعد الإنشاء وقبل توليد التقرير. قد يكون إسنادًا أو تعديلًا؛ ليس دليل أول رد بشري للعميل. المتوسط ومعدل التغطية يعرضان عيناتهما. |
| زمن الإغلاق | completed_at صالح لطلبات مغلقة حاليًا. إعادة الفتح تغيّر القياس؛ ليس سجل إغلاق تاريخي ثابتًا. |
| الطلب المتأخر | طلب من مجموعة الإنشاء له متابعة مفتوحة due_at قبل التوليد، وحالته غير مغلقة. ليست كل مهلة خدمة مؤتمتة أو متفقًا عليها. |
| المهام | مجموعة الاستحقاق وحالة المهمة الحالية. الإنجاز من آخر حدث انتقال مسجل إلى done؛ توقيت ناقص لا يُعد إنجازًا في الموعد. الالتزام = المنجزة في الموعد/عينات الإنجاز الصالحة، مع بيان العينات الناقصة. |
| أداء الموظف | الإسناد الأساسي الحالي للطلبات والمهام؛ ليست نسبة تاريخية لمن خدم العميل أو أغلق الصفقة. يبقى متوسط أول إجراء والإغلاق للموظف متاحًا. |
| تحويلات الجهات | طلبات مختلفة ذات نقل بين فرعين/قسمين بحسب تاريخ سجل النقل، مع فلاتر الطلب والنطاق نفسها. |

التقرير يقرأ لقطة SQLite واحدة للوحة وتصديرها، دون تحديث سجلات الطلبات أو الحالات. البيانات لا تمثل لقطة تاريخية لنهاية فترة قديمة؛ الحالات والإسنادات والتكاليف قد عُدلت بعد ذلك. لا يوجد ادعاء بجودة خدمة أو رضا مثبت أو عائد حملات عند غياب مصدر ربط الحملة والإنفاق والتقييم.

## المبالغ والعملات

العملة الأساسية JOD، لكن لا يوجد في هذه المرحلة مصدر صرف معتمد أو تحويل. تُوحّد JOD وJD ود.أ فقط؛ العملات الأخرى تبقى منفصلة. لا يُحسب مجموع عام بين JOD وUSD، ولا يُستخدم quote_amount كإيراد أو تحصيل.

قيمة الحجوزات: bookings ذات status=confirmed حاليًا وconfirmed_at في الفترة. التكلفة الكاملة والهامش التقديري لا يظهران إلا عند اكتمال تكلفة كل حجوزات عملة المجموعة. يمكن معرفة تغطية التكلفة دون افتراض تكلفة صفر للحجز الذي لا تكلفة له. مبلغ أو تكلفة نصية قديمة ليست رقمًا؛ القيم غير الصالحة/غير المحدودة أو خارج حد القراءة الآمن لا تتحول إلى صفر.

القبض والاسترداد: booking_payments بحسب تاريخ القيد ونوع receipt/refund، بما فيها دفعات حجوزات أُكدت في فترة أقدم أو ألغيت لاحقًا. صافي التحصيل = المقبوض−المسترد بنفس العملة. لا يُعرض صفر مبلغ عند غياب كل قيود تلك العملة. القيد ذو المبلغ غير الصالح يمنع استنتاج صافي كامل.

الرصيد: رصيد حالي لحجوزات فترة التأكيد المؤكدة حاليًا، بعد دفعاتها حتى التوليد. المستحق = max(قيمة الحجز−صافي دفعاته،0)، والزائد للعميل = max(صافي الدفعات−القيمة،0). عملة دفعة مختلفة أو مبلغ غير صالح يجعل الرصيد الكامل غير متاح؛ لا نحول عملة ولا نتجاهل دفعة لنفترض مبلغ دين. ليست هذه كل ذمم الشركة أو كشفًا تاريخيًا لنهاية الفترة.

الهامش المعروض تقديري فقط. لا يوجد دفتر اعتراف بالإيراد وتكلفة فعلية مسددة يثبت ربحًا محققًا. أسعار البرامج ومستندات المورد وعروض الأسعار لا تدخل المبيعات أو القبض تلقائيًا. جداول الحجوزات والدفعات تقرأ كما هي؛ إدخال وتسوية سجلات مالية جديدة ليس ضمن المرحلة الخامسة.

## الأهداف

مقاييس الأهداف: عدد الطلبات، عدد طلبات مجموعة الإنشاء المؤكدة حاليًا، وصافي التحصيل بعملة محددة. للهدف فرع وقسم اختياري وموظف اختياري وفترة واضحة. اختلاف المقياس أو الجهة يعني هدفًا مختلفًا؛ لا تجمع أهداف مستويات مختلفة كأنها هدف واحد.

يُمنع تداخل هدفين نشطين للجهة والموظف والمقياس والعملة نفسها. تغيير الجهة/الفترة/الوحدة يحتاج إيقاف الهدف وإنشاء بديل. تعديل القيمة أو الحالة يحتاج سببًا ومراجعة revision صحيحة؛ التعديل المتزامن القديم مرفوض. كل تعديل له سجل قبل/بعد ومستخدم وتاريخ، ولا حذف للهدف أو تاريخه. سحب الصلاحية أثناء استلام الطلب يمنع الحفظ.

أهداف التحصيل دون دفعات لها نتيجة غير متاحة؛ لا يُخترع تقدم 0%. عند فلترة مصدر/خدمة/فرع استقبال لا تُعرض أهداف جهة كاملة بنتيجة جزئية مضللة؛ امسح هذه المرشحات لعرضها. الهدف المعروض يحسب فترته الكاملة، مع احترام النطاق الحالي؛ أي تغير سابق في الإسناد قد يغير النتيجة الحالية.

## التصدير والأداء والرجوع

الشاشة وCSV ومستند PDF تستعمل المحرك والفلاتر نفسها. CSV عربي BOM واقتباس للفواصل والأسطر والاقتباسات، وحماية من الصيغ التي تبدأ =/+/-/@ بما فيها المسافات السابقة. التفاصيل 50 صفًا للصفحة، وتصدير تفاصيل كامل حتى 10000 صف؛ إذا تجاوزها يُرفض التصدير مع طلب تضييق الفلاتر بدل القطع الصامت.

جداول البعد أول 100 مجموعة، والأهداف أول 50 هدفًا، مع عدد/تحذير صريح. المجاميع تحسب كل الصفوف المطابقة. الرسم يأخذ عينة أيام منتظمة عند طول الفترة، دون تغيير المجاميع أو السلسلة اليومية المصدرة. الفهارس الجديدة تسرّع اختيار فترات الإنشاء/الاستحقاق/التأكيد/القيد.

مستند PDF مصادق عليه وخاص وno-store، مع CSS وخطوط ومكتبات محلية وسياسة CSP مقيدة. يُنشأ PDF العربي في المتصفح كصور صفحات A4، وتُكرر رؤوس الجداول عند تقسيمها. الملف ليس مستندًا موقعًا أو قابلًا للبحث النصي ولا بيانًا محاسبيًا معتمدًا. يحفظ الخادم تدقيق تحضير مستند التصدير، لا إثباتًا بأن المستلم قرأ أو نزّل الملف. إذا تجاوز قسم واحد حد الرسم الآمن يعرض خطأً ويمكن استعمال الطباعة/تضييق الفلاتر دون فقد الصفوف بصمت. البيانات التي نُزّلت لا يمكن سحبها بأثر رجعي.

قبل النشر المعتمد: اعتماد PR16 السابق، مراجعة الصلاحيات، نسخة خاصة حديثة وتجربة clone إلى schema8 والاستعادة. أداة التجربة تقبل schema2/5/6/7، ولا تفتح المصدر للكتابة، وتحتفظ بنسخ كل خطوة ومقارنة الخلايا والسجلات. لا ترفع قاعدة أو تقارير عملاء إلى GitHub. الرجوع لكود قديم لا يخفض schema8؛ أوقف الكتابات واحفظ أحدث البيانات وافحص الفروق قبل استعادة أي نسخة أقدم معتمدة.
