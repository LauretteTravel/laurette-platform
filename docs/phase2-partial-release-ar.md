# تسليم جزئي للمرحلة الثانية دون اعتماد رفع المرفقات

قرار النطاق: إبقاء تجهيز الفاحص للمراجعة دون شراء خدمة إضافية. هذه الدفعة تجهّز اعتمادًا جزئيًا للمرحلة الثانية، ولا تنشرها ولا تعلن اكتمال مواصفاتها. لا تبدأ المراحل 3–6 هنا.

## التغيير

- رفع مرفقات المهام الجديدة مغلق افتراضيًا على الخادم، قبل قراءة الملف أو الاتصال بالفاحص. المتغير `TASK_ATTACHMENT_UPLOADS_ENABLED` لا يفعّل الرفع إلا بالقيمة الحرفية `1`. القيم الغائبة أو المختلفة تبقيه مغلقًا. لا تضع القيمة 1 في إعدادات الإنتاج ما دام الفاحص غير معتمد ومجهزًا.
- يعاد فحص قرار الرفع بعد انتظار نتيجة الفاحص وقبل الكتابة. فحص صلاحيات الجلسة الحديثة وmust_change وMFA وفحص الملفات تبقى مطلوبة؛ المتغير ليس تجاوزًا لها.
- قائمة المرفقات تعرض حالة الرفع، وتخفي الواجهة النموذج عند القفل برسالة واضحة. لا تستطيع واجهة قديمة تجاوز قفل الخادم. يستمر عرض وتنزيل المرفقات المحفوظة للمخولين دون فاحص جديد، وفق تحقق المحتوى والصلاحيات الحاليين.
- لا حذف بيانات، ولا تعديل ترحيل أو checksum أو إعداد Render. تبقى الترحيلات 3–5 مطلوبة لمرشح المرحلة الثانية ولو أُجل الرفع؛ لا يُحذف جدول المرفقات أو يُتخطى سجل الترحيلات.

الملفات: `lib/task-attachments.js`، `public/assets/js/admin.js`، `tests/phase2c.test.js`، `tools/real-clamav-acceptance.mjs`، وهذا التقرير. أداة المحرك الحقيقي تضبط المتغير داخل عملية الاختبار المصطنعة فقط وتستمر في اشتراط نجاح ClamAV؛ لا تُضعف اختبارات العدوى أو التعطل أو الصلاحيات.

## ما يمكن مراجعته للاعتماد الجزئي

المتابعات وصندوق غير المخصص، المهام الفردية والجماعية والتعيين والتعليقات وقوائم التحقق، الإشعارات الداخلية، صفحة المواعيد وعبء العمل والتنبيه والتصعيد ضمن النطاق. سياسة التنبيه تبقى معطلة افتراضيًا إلى أن تُراجع علاقة المدير المباشر وصلاحياته والتوقيتات. لا خدمة إرسال خارجية جديدة في هذه الدفعة.

التعاميم وإقرار القراءة وKanban والتقويم والتسجيل الصوتي المباشر وإدارة المشاركين بعد الإنشاء وأرشيف التعليقات القديم الموسع وبقية فجوات تقارير 2A–2D لا تُعلن مكتملة. المرفقات والملفات الصوتية الجديدة مؤجلة إلى تجهيز فاحص معتمد واختباره. لا يُخلط هذا مع تعطيل القسائم القديمة أو الموقع العام أو حساب العميل أو التتبع أو n8n.

## دليل القبول والخطوة التالية

اختبارات البوابة تتأكد من رفض الرفع دون فحص أو سجل جزئي، وبقاء تنزيل الملف المحفوظ وتفاصيل المهمة، ورفض المستخدم من فرع آخر والمجهول وطلب CSRF. اختبار آخر يقفل الرفع أثناء فحص ناجح ويتأكد من عدم الحفظ. تظل اختبارات الرفع المفعّل والعدوى والمهلة والأنواع والصلاحيات قائمة. أرقام النتائج النهائية وروابط CI تسجل في وصف PR بعد اكتمال التشغيل.

النتيجة المحلية: 174/174 اختبارًا، صفر فشل أو تجاوز، و27/27 فحص دخان. معاينة متصفح محلية بحساب وقاعدة ذاكرة ومرفقات مصطنعة أكدت ظهور رسالة القفل، وعدم وجود نموذج رفع، وبقاء رابطَي تنزيل ومشغل الصوت والصورة المحفوظين. دليل المعاينة: `screens/phase2-partial/disabled-uploads-synthetic.png`. لا بيانات إنتاج في الصورة، وإدخال عينات المعاينة المحفوظة ليس ادعاء اجتيازها فاحصًا حقيقيًا؛ اختبار مسار الرفع الحقيقي مستقل في CI.

قبل أي نشر جزئي: اعتماد المالك لهذا النطاق المؤجل صراحة، مراجعة الرأس النهائي المجمع للمرحلة الثانية وترتيب طلبات المراجعة التابعة، نجاح CI للمرشح النهائي، نسخة خاصة متسقة حديثة وتجربة ترحيل واستعادة معزولة، وحفظ مفاتيح MFA ومسار قاعدة البيانات. لا ترفع تقارير قواعد الإنتاج أو نسخها إلى المستودع العام. مراجعة دورات العمل والصلاحيات والسياسات لا تُستبدل بمجرد نجاح الاختبارات.

الرجوع: يمكن قفل الرفع بإزالة المتغير أو جعله 0 ثم إعادة تشغيل الخدمة دون تغيير البيانات. لا ترجع تلقائيًا إلى كود يرفض المخطط 5، ولا تستبدل قاعدة حية بنسخة أقدم. عند الحاجة للرجوع، أوقف الكتابات واحفظ الحالة وصالح الأعمال اللاحقة مع نسخة معزولة متوافقة، أو نفذ إصلاحًا أماميًا. لا دمج أو نشر دون موافقة صريحة.
