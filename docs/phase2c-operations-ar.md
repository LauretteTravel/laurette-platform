# تشغيل 2C والرجوع

لا نشر قبل اعتماد الدفعات وتجهيز الفاحص الحقيقي. الإنتاج الحالي على مخطط 2؛ يشغل runner الترحيلين 3 و4 بالترتيب، مع snapshot قبل كل خطوة. لا تعدّل checksum لأي ترحيل معتمد.

1. جهّز clamd على 127.0.0.1:3310 داخل بيئة الخدمة، أو عبر نفق محلي محمي. يمكن تغيير المنفذ عبر ATTACHMENT_CLAMD_PORT فقط. لا يُرسل إلى عنوان خارجي ولا يُفتح منفذ clamd للإنترنت. لم تتغير Dockerfile أو إعدادات Render في هذا الطلب.
2. راجع سعة المضيف وتشغيل AV وتحديث التواقيع عبر freshclam ومراقبة عمرها. اضبط StreamMaxLength ليسمح بـ5MiB على الأقل، وحدود الفحص حسب سياسة الشركة. اختبر بمحرك حقيقي داخل staging ملفًا سليمًا وعينة فحص مصرحًا بها، وحالات إيقاف الخدمة والتواقيع الغائبة أو المتقادمة والمهلة والحمل والذاكرة. لا تستخدم ملف عميل حقيقي لهذا الاختبار. المحاكي الحالي لا يعوض هذه الخطوة.
3. راجع مساحة القرص: 1GiB للمحتوى، إضافة إلى SQLite وWAL والنسخ ومحرك AV. الحد 5MiB للملف و20 ملفًا و50MiB للمهمة. لا تملأ قرص الإنتاج.
4. احفظ نسخة SQLite متسقة خاصة قبل النشر، وجرّب استعادتها في عزل. بعد الترحيل افحص integrity_check وforeign_key_check ودفتر 1–4 ومحتوى المرفقات وSHA256 والصلاحيات. النسخ الحقيقية تحتوي ملفات وبيانات حساسة ولا تُرفع إلى Git. احتفظ بمفاتيح MFA الأصلية منفصلة.
5. بعد الاعتماد والنشر فقط، تحقق بحسابات مصرح بها من الرفع والتشغيل والتنزيل وإبطال الوصول وعدم وجود رابط عام. غياب ClamAV يرجع 503 دون مسار لتجاوز الفحص.

## الرجوع

الكود السابق يرفض مخطط 4. لا يكفي Rollback في Render، ولا يُغير user_version يدويًا. أوقف الكتابات واحفظ الحالة الحالية، واستعد snapshot الإصدار السابق في عزل، وصالح كل الأعمال والمرفقات اللاحقة قبل أي تبديل بموافقة المالك. لا تُسقط جدول المرفقات ولا تستبدل قاعدة حية بنسخة قديمة. يمكن استخدام إصلاح أمامي متوافق مع 4. لا ترحيل عكسي تلقائي؛ الاستعادة المختبرة مصطنعة فقط.

[مرجع بروتوكول ClamAV الرسمي](https://raw.githubusercontent.com/Cisco-Talos/clamav/main/docs/man/clamd.8.in): INSTREAM بأمر z ونهاية NULL، وأطوال chunks من أربعة بايت بترتيب الشبكة، وحجم صفر للإنهاء. نجاح البروتوكول لا يثبت جودة التواقيع أو كشف جميع التهديدات.
