# تقرير الدفعة 2D — المواعيد والتنبيهات والتصعيد

الحالة: للمراجعة فقط على codex/employee-operations-phase-2d ، مبنية على 2C@6e1068b. لا دمج أو نشر أو تعديل للإنتاج. الطلب متسلسل بعد 2A و 2B و 2C. التدقيق قبل التنفيذ في phase2d-audit-ar.md.

## المنجز

- لوحة عبء العمل والمواعيد من المهام والمتابعات المفتوحة المخولة، مع أعداد المفتوح والمتأخر والقريب، وتصفية حسب المسؤول وروابط للسجلات الأصلية وترقيم 25 عنصرًا لكل صفحة. القياس أعداد سجلات وليس ساعات جهد أو تقييم أداء أو SLA مفترضًا لطلبات بلا موعد.
- تنبيه قرب الموعد للموظف، وتنبيه تأخير، وتصعيد واحد للمدير المباشر المسجل في ملفه، إذا كان نشطًا ومخولًا أصلًا بالسجل وصلاحية الإسناد. لا مدير بديل أو توسيع صلاحيات أو تغيير حالة وإسناد أو رسائل خارجية.
- سياسة معطلة افتراضيًا، تضبطها إدارة المؤسسة بسبب ورقم نسخة: قرب الموعد 15–1440 دقيقة، والتصعيد 60–10080 دقيقة بعد التأخير. القيم المقترحة 60 و 1440 لا تعمل حتى التفعيل الصريح داخل النظام بعد اعتماد النشر.
- مجدول كل 60 ثانية، و 500 عنصر كحد أقصى للدورة مع مؤشر استكمال دائم. الدفعة معاملة واحدة؛ حد الإشعارات النظري 1000 للدورة. تتم معالجة الدفعات التالية دون أن يمنع تكرار القديم الوصول إليها؛ زيادة الصف قد تؤخر التسليم لعدة دورات.
- ترحيل 5 يضيف operations_alerts وفهارس تفرد لكل مستلم وعنصر وموعد ومسؤول ونوع. السجل يحتفظ بالتاريخ ويمنع حذف الهوية أو تعديلها. لا تكرار بعد إعادة التشغيل، ولا تكرار عند التشغيل اليدوي المتتابع.
- قائمة تنبيهات مواعيد مستقلة من 50 عنصرًا لكل صفحة مع عداد غير مقروء وتسجيل قراءة وروابط. إشعارات تحديثات المهام السابقة تبقى كما هي.
- إخفاء التنبيه والعداد عند إغلاق العنصر أو تغيير موعده أو مسؤوله أو زوال نطاق الوصول. التصعيد يختفي إذا تغير المدير المباشر أو فقد صلاحية الإسناد. العضويات الإضافية النشطة تدخل اختيار المستلم؛ العرض يلتزم بسياق الجلسة الحالي.
- ست نقاط API عبر RBAC و MFA و must_change و CSRF. إعداد السياسة وتشغيل دورة يدويًا يتطلبان organization:write ونطاق المؤسسة. تشغيل المجدول لا ينفذ استدعاء HTTP ولا يمنح استثناء مصادقة للمستخدم.

## التحقق

167/167 اختبارًا ناجحًا، صفر فشل/تجاوز، منها 10 اختبارات جديدة. الدخان 27/27. مصفوفة 95 مسارًا×3=285 حالة رفض دون كتابة أعمال، و 8 أدوار×95=760 قرار صلاحية. الحساب والتتبع والقسائم و n8n و MFA والمرفقات باقية. فحص الصياغة والفرق ناجح؛ CI يُراجع على PR.

الاختبارات تغطي السياسة المعطلة والسبب والتعارض و CSRF ، قرب الموعد ثم التأخير ثم التصعيد مرة واحدة، منع توجيه التصعيد لمدير غائب أو معطل أو خارج الفرع أو غير مخول، متابعات الطلب، القراءة والعزل وإخفاء التنبيهات القديمة، دقة الأعداد والترقيم، التراجع الكامل عند فشل الإدراج، وحفظ منع التكرار بعد إعادة فتح القاعدة. اختبار 501 عنصرًا يثبت استكمال الدفعات المحدودة. ترقية 4 إلى 5 مع snapshot قابل للاستعادة وحفظ دفتر 1–4 وفحص سلامة القاعدة ناجحة على بيانات مصطنعة.

فحص متصفح محلي بحسابات مصطنعة: دخول MFA ، 5 عناصر مفتوحة، 3 متأخرة وواحد قريب؛ تفعيل سياسة محلية 60/120 بسبب، وتشغيل أول أنشأ 6 تنبيهات ومنها تصعيدان للمشرف؛ التشغيل التالي أنشأ 0 ، وظهرت روابط المهمة والمتابعة في تنبيهات المشرف. لا تفعيل إنتاج أو حسابات حقيقية.

## الحدود والمتبقي

يحتاج المالك لاعتماد التوقيتات وتدقيق علاقات المدير المباشر وصلاحياتهم قبل تفعيل السياسة بعد النشر. التنبيهات داخل الصفحة المخصصة؛ لا push أو WhatsApp أوبريد. لا تعاميم أوإقرار قراءة أو Kanban أوتقويم أوتصعيد متعدد المستويات أوقواعد حسب الخدمة/الأولوية. لا احتساب أوقات عمل أوعطلات، ولا ضمان SLA دقيق للتسليم؛ التوقيتات مدد زمنية فعلية منذ due_at.

المجدول يعمل داخل عملية التطبيق فقط؛ لا يعمل أثناء توقف الخدمة، ويلتقط المتأخر عند الدورة التالية بعد العودة. قرب الموعد الذي فات أثناء التوقف لا يرسل بأثر رجعي، بل يصبح تنبيه تأخير. المعالجة دورية وعلى دفعات، ولم يجر اختبار ضغط إنتاج أو تدقيق شامل للجوال والوصول. تغيير موعد قديم والعودة إلى الموعد والمسؤول نفسيهما يستعمل سجل التفرد السابق ولا يعيد نفس التنبيه.

لا تعني هذه الدفعة اكتمال كل مواصفات المرحلة 2 ؛ الفجوات أعلاه وبقية حدود 2A–2C باقية، ومنها تجهيز ClamAV حقيقي قبل نشر المرفقات. المراحل 3–6 لم تبدأ.
