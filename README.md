# منصة لوريت للسياحة والسفر

منصة تشغيل كاملة لشركة **لوريت للسياحة والسفر والحج والعمرة**: موقع عربي (RTL) لست خدمات، ونظام طلبات حقيقي بقاعدة بيانات، ولوحة إدارة بصلاحيات، ومساعد آلي مربوط بقاعدة المعرفة، وتحسين ظهور تقني.

النسخة تعمل محليًا **بصفر اعتماديات خارجية**: خادم `node:http` مدمج، وقاعدة `node:sqlite` مدمجة، وواجهة بلا أطر عمل. لا `npm install`، ولا مفاتيح API في الواجهة.

---

## 1. التشغيل السريع

```bash
cd laurette-platform
node server.js          # أو: npm start
```

- الموقع: `http://127.0.0.1:3000`
- لوحة الإدارة: `http://127.0.0.1:3000/admin`
- بيانات الدخول المؤقتة: `data/admin-credentials.txt` (تُنشأ مع أول بناء للبيانات)

> **مصدر الحقيقة لكلمة المرور هو `data/admin-credentials.txt`.** يُنشئ الخادم حساب المدير بكلمة المرور هذه عند أول زرع؛ ولا يُخزَّن النص الصريح في `seed.json`.

> **غيّر كلمة المرور فورًا** من «الإعدادات ← كلمة المرور». النظام يطالبك بذلك بعد الدخول.

### أول تشغيل

1. إن لم تكن `data/laurette.db` موجودة، تُنشأ تلقائيًا ويُزرع المحتوى من `data/seed.json`.
2. إن كان الملف موجودًا، لا يُعاد الزرع (لا تُلمس الطلبات والعملاء).
3. لإعادة بناء المحتوى المرجعي فقط: `npm run seed` — يمسح البرامج/العروض/الأخبار/المداخل ويعيدها من الكتالوج المستخرج، ويحفظ الطلبات.
4. لتصفير حساب المدير: `node tools/reset-admin.mjs`.

### متغيرات البيئة

| المتغير | الافتراضي | الغرض |
|---|---|---|
| `PORT` | `3000` | منفذ الخادم |
| `HOST` | `127.0.0.1` محليًا، `0.0.0.0` في الإنتاج | واجهة الاستماع |
| `BASE_URL` | `http://HOST:PORT` | يُستخدم في canonical وsitemap وروابط واتساب والتحقق من الأصل |
| `DB_FILE` | `data/laurette.db` | مسار قاعدة SQLite |
| `ADMIN_PASSWORD` | اختياري محليًا | كلمة مرور المدير الأولية عند إنشاء قاعدة جديدة. يضبطها النشر السحابي كمتغير سري؛ محليًا ينشئ `npm run seed` ملف بيانات دخول مستثنى من Git وDocker |
| `RESEND_API_KEY` | فارغ | مفتاح Resend لإرسال رموز تأكيد حساب العملاء. مطلوب لتفعيل التسجيل |
| `EMAIL_FROM` | فارغ | عنوان المرسل الموثق لدى Resend، مثل `Laurette <accounts@example.com>` |
| `LLM_API_URL` / `LLM_API_KEY` / `LLM_MODEL` | فارغة | طبقة اختيارية للمساعد (OpenAI-compatible). بدونها يعمل المساعد المحلي بنفس الضوابط |
| `LOG_REQUESTS` | `0` | سجل وصول مختصر |

### الطلبات (قلب النظام)

- ستة أنواع: `flight`, `hotel`, `program`, `umrah`, `visa`, `consult`.
- أرقام مرجعية: `LT-FL-…`, `LT-HT-…`, `LT-PG-…`, `LT-UM-…`, `LT-VS-…`, `LT-CS-…` (6 خانات عشوائية، `UNIQUE`).
- تحقق خادمي لكل حقل (هاتف، بريد، تواريخ منطقية، حدود المسافرين، أعمار الأطفال، enums) — الواجهة تحقق أيضًا لكن القرار للخادم.
- منع التكرار: نفس النوع + نفس الهاتف + نفس الحمولة داخل 15 دقيقة → يعيد نفس الرقم المرجعي بلا صف جديد.
- كل طلب يُنشئ/يحدّث ملف عميل (مفتاح الدمج: الهاتف مطبّعًا).
- حالة الطلب: `new → reviewing → quoted → awaiting → confirmed | cancelled` مع رفض أي انتقال غير مسموح.
- سجل أحداث لكل تغيير (إنشاء، حالة، إسناد، عرض سعر، ملاحظة) مع الفاعل والوقت.
- عرض السعر يظهر للعميل في `/track`.

### حساب العميل وتتبع الحجوزات

- `/account`: إنشاء حساب بالبريد المؤكد، ثم لوحة طلبات السفر. `/account/profile`: تحديث الاسم ورقم الهاتف.
- التسجيل يتطلب الاسم الأول واسم العائلة والبريد وكلمة مرور ورقم هاتف. قائمة رموز الاتصال مرتبة أبجديًا وتضم 248 بلدًا وإقليمًا مع الأعلام.
- يُرسل OTP عشوائي من 6 أرقام عبر Resend، وتُخزن كلمة مرور بطيئة التجزئة للرمز، بصلاحية 10 دقائق مع تحديد محاولات التحقق وإعادة الإرسال. لا تُنشأ جلسة قبل تأكيد البريد.
- جلسات العميل منفصلة عن دخول الموظفين، عبر كوكي HTTP-only وSameSite=Strict لمدة 30 يومًا. واجهات الحجوزات والملف الشخصي لا تقبل معرّف عميل من المتصفح؛ وتعيد بيانات الجلسة الموثقة فقط.
- تعرض لوحة العميل رقم الطلب والنوع والملخص والحالة وتاريخ الإرسال وعرض السعر وملاحظته الموجهة للعميل وسجل تغييرات الحالة. لا تُرسل حمولة الطلب أو الملاحظات الداخلية.
- عند توثيق البريد، تُربط الطلبات السابقة التي تتضمنه. الطلبات الجديدة تُسجل مباشرةً لحساب العميل عند إرسالها أثناء تسجيل الدخول.
- يتطلب إرسال البريد إعداد `RESEND_API_KEY` و`EMAIL_FROM` (مرسل موثق في Resend). أخطاء الإرسال تظهر للعميل، ولا يُكشف رمز OTP في الصفحة أو استجابة API.
- ملف أرقام الهاتف ثابت من [mledoze/countries](https://github.com/mledoze/countries)، بترخيص بيانات ODbL-1.0، ويُخدم من `/assets/data/phone-codes.json`.

### لوحة الإدارة

نظرة عامة بعدادات حقيقية (جديدة، تحتاج متابعة، عروض مرسلة، عملاء، توزيع الأنواع) + **تقارير أداء (يومي/أسبوعي/شهري)** + الطلبات (تصفية/بحث/درج تفاصيل/تغيير حالة/إسناد/عرض سعر/ملاحظة/سجل/واتساب العميل) + CRM (ملف عميل وطلباته وملاحظات الموظف) + البرامج (CRUD مع أرشفة تلقائية إن كان البرنامج مرتبطًا بطلبات) + المحتوى (عروض، أخبار، مقالات، أسئلة، وجهات، مراجعات) + التأشيرات + قاعدة معرفة المساعد + **التسويق والتتبع (Meta Pixel / GTM / Google Ads)** + الموظفون والصلاحيات + الإعدادات + سجل العمليات + محادثات المساعد.

### تتبع الصفقات وتقارير الأداء

- كل طلب يحمل **مرحلة صفقة** (`new` جديد، `in_progress` قيد المتابعة، `won` مكتملة، `lost` ملغية) مشتقة تلقائيًا من حالة الطلب، مع `completed_at` عند الإغلاق و`first_response_at` عند أول إجراء من الموظف.
- **مدة الإنجاز** تُحسب بالدقائق/الساعات/الأيام وتظهر في تفاصيل الطلب وتقرير المدير.
- تقارير **يومية/أسبوعية/شهرية** + مدى مخصص + فلترة بالموظف: إجمالي الطلبات، الصفقات الناجحة/الملغية، نسبة التحويل ومعدل الفوز، متوسط زمن الإنجاز وأول استجابة، قيمة الصفقات، أداء كل موظف، التحويل حسب الخدمة، قمع الحالات، رسم بياني زمني.
- تصدير CSV لجدول أداء الموظفين، وصلاحيات `reports:read` للمدير ومدير القسم فقط.

### التسويق والتتبع

- إعدادات من اللوحة لـ **Meta Pixel ID** و**GTM ID** و**Google Ads Conversion ID + Label** ومفتاح تفعيل عام.
- حقن الأكواد في `<head>` بـnonce، وتحميلها **بعد load وفي وقت خامل** (‏لا تؤثر على الرسم الأول)، مع `noscript` لـGTM والبكسل.
- أحداث: `Lead` + `SubmitApplication` عند نجاح أي طلب (طيران/فندق/تأشيرة/عمرة/برنامج/استشارة)، و`Contact` عند اختيار رقم واتساب فعلي.
- إرسال `generate_lead`/`whatsapp_click` إلى dataLayer، وتسجيل مجهول للأحداث في `tracking_events` للتحقق (بلا أسماء أو هواتف).
- سياسة CSP تتوسّع تلقائيًا لنطاقات Meta/Google فقط عند إضافة المعرفات، وتُحترم إشارة `Do Not Track`.

### المساعد الآلي

- إجابات من بيانات القاعدة فقط (برامج، أسعار «تبدأ من»، فنادق، تأشيرات، أسئلة، سياسات).
- يفهم العربية الفصحى واللهجة الأردنية عبر تطبيع النص وكلمات مفتاحية وعبارات (بدي أسافر، كم، ميزانية…).
- لا يخترع أسعارًا: كل رقم يُذكر مأخوذ من `programs.price_from`، وإلا يحوّل لموظف.
- لا يضمن تأشيرة، ولا يدّعي تنفيذ حجز، ويذكر مصدر المعلومات وتاريخ آخر تحديث.
- يحفظ المحادثة **فقط** بعد موافقة صريحة (مربع اختيار)، والجلسة والمحتوى في جداول مستقلة.
- طبقة LLM اختيارية: إن فُعّلت، يُرفض أي رد يحتوي سعرًا غير موجود في السياق المسترجع (فحص آلي)، ويعود للمسار المحلي.

### SEO والبنية التقنية

عناوين وأوصاف فريدة، canonical مطلق، Open Graph/Twitter، JSON-LD (`TravelAgency`, `WebSite`, `Product/Offer`, `BreadcrumbList`, `FAQPage`, `Article`, `TouristDestination`)، `sitemap.xml` مولّد من القاعدة، `robots.txt` يمنع `/admin` و`/track` و`/api`، صفحات وجهات وخدمات قابلة للفهرسة، خط `Cairo` مع `display=swap`، صور SVG أصلية مولّدة على الخادم (بلا أصول خارجية أو أسعار نقل صور)، تخطيط RTL بخصائص منطقية وجاهزية LTR، تباين نصوص أعلى، حالات فراغ/خطأ واضحة.

### الأمان

- كلمات المرور: `scrypt` بملح لكل مستخدم (لا توجد كلمة مرور أو بصمة في الواجهة).
- الجلسات: توكن 32 بايت، يُخزَّن **مُهشَّرًا** في القاعدة، كوكي `HttpOnly; SameSite=Strict; Path=/` (و`Secure` تلقائيًا على HTTPS)، انتهاء 8 ساعات.
- تحديد محاولات الدخول: 5 إخفاقات/10 دقائق لكل IP+مستخدم، وحد 12 طلب دخول/10 دقائق.
- CSRF: كتابة API تتطلب `X-Requested-With: fetch` أو أصلًا مطابقًا.
- حقن HTML: كل مخرجات SSR تمر عبر `esc()`، والمحتوى الغني عبر Markdown آمن (تهريب أولًا).
- رؤوس: CSP بـ nonce لكل طلب، `nosniff`, `frame-ancestors 'none'`, `Referrer-Policy`, `Permissions-Policy`, HSTS على HTTPS.
- صلاحيات: `admin` (كل شيء) / `manager` (طلبات ومحتوى وبرامج وتأشيرات وسجل) / `agent` (طلبات وعملاء وقاعدة معرفة فقط).
- سجل تدقيق لكل إجراء إداري مع IP والوقت.
- بيانات الحساسة: لا رفع جوازات عبر الموقع؛ الصفحات تنص على التسليم في الفرع أو قناة آمنة.

- 17 عرضًا ببوسترات الشركة الأصلية (نسخة عرض 900px ونسخة مصغرة 480px) مع السعر والمدة وقائمة «يشمل» لكل عرض.
- 5 تعاميم طيران، 5 مقتطفات مراجعات Google، فرعان و5 أرقام واتساب، 26 وجهة، 6 مقالات، 14 سؤالًا، 6 أدلة تأشيرات، 18 مدخل معرفة.

> **عن الأسعار:** كل رقم معروض مأخوذ حرفيًا من بيانات الشركة السابقة (أدنى سعر بين خيارات الغرف/الكابينات)، ويُعرض بصيغة «يبدأ من» مع تنبيه أن السعر النهائي في العرض الرسمي. لا توجد أسعار مُقدَّرة أو مُولّدة.

## 5. النسخ الاحتياطي والاستعادة

- النسخة الكاملة = `data/laurette.db` (+ `data/seed.json` و`data/admin-credentials.txt`).
- مع WAL، انسخ الملفات الثلاثة `laurette.db`, `-wal`, `-shm` بعد إيقاف الخادم، أو استخدم:
  ```bash
  node -e "const {DatabaseSync}=require('node:sqlite');new DatabaseSync('data/laurette.db').exec(\"VACUUM INTO 'backup.db'\")"
  ```
- للاستعادة: أوقف الخادم، استبدل ملف القاعدة، أعد التشغيل.

## 6. النشر إلى Railway

المشروع مهيأ للنشر عبر `Dockerfile` و`railway.json`. قبل الربط، ارفع مجلد المشروع إلى مستودع Git خاص، مع التأكد من أن `data/seed.json` لا يحتوي كلمة مرور (يُنشئ `npm run seed` الملف بهذه الصورة). ملفات قاعدة البيانات وبيانات الدخول والسجلات مستثناة من Docker.

1. أنشئ مشروعًا جديدًا في Railway واربطه بمستودع Git.
2. أضف Volume إلى الخدمة بمسار التركيب `/data`.
3. أضف متغيرات الخدمة:
   - `DB_FILE=/data/laurette.db`
   - `ADMIN_PASSWORD` = كلمة مرور قوية وفريدة كقيمة سرية. تلزم عند إنشاء قاعدة بيانات جديدة.
   - `RESEND_API_KEY` و`EMAIL_FROM` = إعدادات Resend لإرسال OTP، مع عنوان مرسل موثق.
4. أنشئ نطاقًا عامًا للخدمة. يلتقط التطبيق `PORT` و`RAILWAY_PUBLIC_DOMAIN` تلقائيًا؛ ويمكن ضبط `BASE_URL=https://<النطاق-العام>` لضمان الروابط القانونية وخريطة الموقع.
5. انتظر نجاح فحص الصحة `/health`، ثم سجّل الدخول إلى `/admin` وغيّر كلمة المرور إذا طُلب ذلك.

لا ترفع `data/laurette.db` أو `data/admin-credentials.txt` إلى Git. قاعدة البيانات التشغيلية تحفظ على الـVolume، ولا تُعاد تهيئتها عند كل نشر.

### حفظ نسخة المشروع على GitHub

المستودع الخاص هو الخيار الآمن. يستثني `.gitignore` قواعد البيانات، وملف كلمة مرور الإدارة، وملفات البيئة والسجلات والمفاتيح الخاصة. بعد إنشاء مستودع فارغ على GitHub، اربطه من مجلد المشروع:

```bash
git remote add origin https://github.com/OWNER/REPOSITORY.git
git push -u origin main
```

استبدل `OWNER/REPOSITORY` باسم حسابك واسم المستودع. راجع `git status` قبل الرفع، ولا ترفع ملف `.env` أو قاعدة بيانات العملاء حتى إلى المستودع الخاص.

### استضافة ذاتية

1. خادم Linux بـ Node 24 LTS، والمشروع في مسار ثابت.
2. `BASE_URL=https://laurette.example PORT=3000 node server.js` خلف Nginx/Caddy مع HTTPS.
3. الوكيل يمرر `X-Forwarded-For` و`X-Forwarded-Proto`؛ الكود يفعّل `Secure` تلقائيًا عند HTTPS.
4. نسخ احتياطي يومي للقاعدة، ومراقبة `/health`.
5. غيّر كلمة مرور المدير، وأنشئ حسابًا لكل موظف بدل مشاركة حساب واحد.
